# v3.1.0 — Nessus Manual Scan

Threat Intelligence navigation: Nessus Manual Scan, Nessus Scan Result, Vulnerability Scan, Scan Result, Vulnerabilities. Administration includes Nessus Host Mapping.

Upload accepts `.nessus` or `.xml` exports up to 25 MB. Upload and Analyse File are separate actions. The XML parser uses defusedxml and reads ReportHost/ReportItem entries into dedicated import and finding tables. All findings start in Nessus Scan Result → New and use New, Under Review, Accept and Reject states.

Accepting a finding requires at least one valid CVE. It creates or links records in the same `threat_intelligence` table used by Telegram findings. Existing non-empty register fields are preserved; source report and Nessus evidence are appended to source context. Findings without CVEs remain in Nessus Scan Result.

Host mapping rules match hostname, FQDN, IP, MAC or UUID to an administrator-defined actual hostname for future analyses. Original identifiers are preserved.

Migration 0008 is additive and creates `nessus_imports`, `nessus_findings`, and `nessus_host_mappings`. Downgrade drops those tables and deletes Nessus import data. Runtime migration, UI, and API tests remain required. A real Nessus export is needed to verify field variations.
